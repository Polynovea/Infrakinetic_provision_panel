## Correction — the earlier "91 failed / 98 failed" claim was invalid evidence

You caught a real methodology error in the prior version of this document. The earlier run was `cd api-server && npx
vitest run`, and some test files compute paths via `path.join(process.cwd(), "api-server", ...)` — correct when run
from the repo root, but doubled to `.../CRM/api-server/api-server/...` when `process.cwd()` is already `api-server`.
That produced 91 spurious `ENOENT` failures that do not reflect real state. The correct invocation, from the CRM
repository root, is:

```
npx vitest run api-server
```

which produces **302 passed files / 2 failed / 7 skipped, 2409 passed tests / 2 failed / 64 skipped**. This phase's
own file (`routes/management/v1/__tests__/index.test.js`) is 26/26 within that run. The prior "91/98" claim and the
"materially worse baseline than 1A.6" framing built on it are retracted.

## Isolation proof — the 2 genuine failures are not a 1A.7 regression

The two real failures against the current working tree are `api-server/src/lib/__tests__/employmentOfferCapability.test.js`
and `api-server/src/migration/__tests__/platformCatalogBuilder.test.js`. Per your instruction, causality was
established with an isolated worktree rather than argued from inspection alone — the CRM working tree currently
carries ~68 unrelated, uncommitted Document Engine files, so any claim about what causes what needs the delta
mechanically separated from that noise, not just asserted.

**Method**: two `git worktree`s created detached at the current CRM HEAD (`7bca5ad`, the same commit `git status` at
this session's start showed as `HEAD`), with `node_modules` reused via filesystem junctions (no reinstall, no
dependency drift):

- `1a7-baseline` — clean HEAD, nothing else. No Document Engine dirt, no 1A.7 delta.
- `1a7-delta` — clean HEAD + **only** the exact 1A.7 delta copied in: `lib/tenantRegistry.js` (new),
  `routes/management/v1/index.js`, `routes/management/v1/__tests__/index.test.js` (both modified). Confirmed via
  `git status` inside that worktree that these three paths are the *only* diff from HEAD.

**Results**:

| Tree | `employmentOfferCapability.test.js` + `platformCatalogBuilder.test.js` |
|---|---|
| Current working tree (dirty, ~68 unrelated Document Engine files) | **FAIL** (2 failed, 28 passed) — reproduces your finding |
| `1a7-baseline` (clean HEAD, no 1A.7) | **PASS** (30/30) |
| `1a7-delta` (clean HEAD + 1A.7 delta only) | **PASS** (30/30 for these two files; 56/56 including this phase's own 26-test file run alongside them) |

**Root cause, identified directly rather than left as a guess**: `platformCatalogBuilder.test.js` compares a freshly
generated migration destination catalog against a committed snapshot and fails on drift —
`tableCount: 508` (generated) vs `506` (committed snapshot), `missingAdapterCount: 17` vs `15`, including a
`dsp_deliveries` table absent from the committed snapshot. This is exactly the shape of a concurrent, uncommitted
Document Engine migration having been added without its derived catalog snapshot being regenerated to match — a
real, pre-existing gap in the *current dirty tree*, proven absent from both the clean committed baseline and from
1A.7's own delta.

**Conclusion**: the two failures exist only in the current dirty working tree, are absent from clean git history, and
are absent from clean history plus 1A.7. They are concurrent-work artifacts, not a 1A.7 regression and not a
regression against committed history either. Per your instruction ("if the two failures exist without 1A.7, record
them as baseline/concurrent-work failures with proof") — they don't even reach "baseline": they don't exist in clean
committed history at all, only in the uncommitted concurrent work sitting on top of it.

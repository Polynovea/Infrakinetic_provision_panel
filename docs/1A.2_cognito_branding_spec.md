# Cognito Managed Login branding spec — `polynovea-platform-operators`

Date: 2026-09-16

Prepared as part of the 1A.1–1A.7 closure + product-quality pass, per the master task's §9 ("Improve Cognito
Managed Login branding as far as AWS supports without replacing the authentication architecture"). This is a
checklist to apply in the AWS Cognito console (Managed Login branding editor, Managed Login v2) — no code
changes accompany this file, and applying it requires AWS console access this session doesn't have.

## Hard boundary (unchanged)

Do not build a custom password/MFA UI. This spec only covers Cognito's own supported branding surface (logo,
colors, copy, layout within Cognito's template). The authentication architecture recorded in `docs/1A.2_status.md`
(dedicated pool, MFA mandatory, Authorization Code + PKCE, backend-owned session) is not touched.

## Colors — pulled directly from `frontend/app/globals.css`'s Imperial Night/Ivory tokens

Cognito's Managed Login branding editor exposes primary/background/text/error color slots. Use:

| Cognito slot | Value | Source token |
|---|---|---|
| Primary button background | `#d8b56a` (dark) / `#4a2b58` (light, if Cognito's editor is set to match a light preference) | `--action-primary` |
| Primary button text | `#0b0910` (dark) / `#f5f1e8` (light) | `--action-primary-text` |
| Page background | `#0b0910` | `--bg-canvas` (dark) |
| Form/card surface | `#121017` | `--bg-surface-1` (dark) |
| Body text | `#f5f1e8` | `--text-primary` (dark) |
| Muted/secondary text | `#938a98` | `--text-muted` (dark) |
| Link color | `#e0c17d` | `--link` (dark) |
| Error text | `#f28c94` | `--danger-fg` (dark) |
| Error background | `#321518` | `--danger-bg` (dark) |
| Focus ring | `#e0c17d` | `--focus-ring` (dark) |
| Border | `#2d2732` | `--border-subtle` (dark) |

Cognito's Managed Login does not support `prefers-color-scheme` — pick one fixed theme. Recommend **dark**
(Imperial Night), since it's this product's flagship expression (per `globals.css`'s own comment) and matches
the operator console's own default rendering in most terminals/monitors used by platform operators.

## Logo

Upload a PolyNovea wordmark or monogram if one exists as a static asset (Cognito accepts PNG/SVG/JPEG up to its
documented size limit — check the current Cognito console for the exact limit at upload time). If no approved
logo asset exists yet, skip this — do not improvise one.

## Copy

Cognito's Managed Login lets you override some template strings. Where supported:

- Page title: "PolyNovea Platform Governance"
- Sign-in button label: "Sign in"
- Error banner copy should stay Cognito's own (this session should not invent custom error microcopy without
  the product owner reviewing it — Cognito's default error text is already reasonable and does not leak
  implementation detail).

## What NOT to change

- MFA prompt wording/flow — leave as Cognito's own TOTP challenge screen.
- Password policy messaging — leave as Cognito's own.
- Do not add a "forgot password" custom flow beyond what Cognito's template already offers, unless a future
  phase explicitly scopes self-service password recovery for operators.

## How to apply

1. AWS Console → Cognito → User pools → `polynovea-platform-operators` → App integration → Managed login pages
   (or "Branding" depending on current console version) → select the app client this backend uses.
2. Switch to "Managed login version 2" branding editor if not already active (per `docs/1A.2_status.md`, v2
   branding was already applied at pool provisioning — this spec is a refinement, not a first application).
3. Set colors per the table above under the branding editor's color tokens (names may differ slightly from
   Cognito's UI labels — match by role: primary action, background, surface, text, muted text, link, error,
   focus, border).
4. Upload the logo if available.
5. Update copy fields where supported.
6. Preview in the console's live preview pane before publishing.
7. Publish, then do a real sign-in pass (this is part of Phase B/G's live certification, not a separate step)
   to confirm the branded page renders correctly and the sign-in flow still works end-to-end.
